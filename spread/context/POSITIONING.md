## Qué vende, qué hace, qué guarda

| | |
|---|---|
| **Lo que vende** | Qualified pipeline. |
| **Lo que hace** | Targeting + brand/message + outbound + web + ads + automation + measurement. |
| **Su ventaja interna** | evidence → opportunity → decision → intervention → outcome → learning |
| **Lo que ve el cliente** | target companies → outreach + ads → website → meeting → pipeline |

**Mecanismo, no categoría.** El cliente no compra signals, agents, distribution ni decision
architecture: son el mecanismo interno. Tampoco se sale a vender Decision Intelligence, Revenue
Capture u Opportunity Engine. «Signal» puede seguir existiendo en la arquitectura interna; no es la
palabra con la que se sale al mercado. Incluso «GTM» se reduce: sirve para hablar con gente del
sector, no como propuesta principal.

**Qué compra realmente el cliente**

- Más empresas correctas entrando al pipeline.
- Más reuniones calificadas.
- Mejor conversión de su tráfico.
- Menos trabajo manual.
- Claridad sobre qué está generando oportunidades.

**La propuesta, en tres líneas**

- Problema: *We need more qualified pipeline.*
- Respuesta: *We build the system that generates it.*
- Cómo: *Targeting + messaging + outbound + web + paid + automation + attribution.*

## Oferta V1 (propuesta del 3/9): Pipeline Build

*For B2B SaaS companies that need a repeatable way to generate qualified sales opportunities.*
En castellano: te construimos el sistema completo para convertir tu mercado objetivo en
conversaciones comerciales calificadas.

| # | Componente | Qué incluye | Beneficio para el cliente |
|---|---|---|---|
| 1 | ICP + Offer | Quién compra, qué problema urgente tiene, qué trigger importa, qué oferta y qué mensajes | Dejar de perseguir empresas que nunca iban a comprar. |
| 2 | Account Research | Universo de empresas, research, enrichment, prioridades, contexto | Una lista concreta de empresas que vale la pena atacar. |
| 3 | Outbound | Emails, LinkedIn, secuencias, personalización, follow-ups, routing, automatización | Conversaciones con esas empresas sin trabajo manual constante. |
| 4 | Web + Conversion | Landings, home, páginas verticales, casos, forms, demo flow, personalización, copy, proof | Que el interés generado se convierta en reunión. |
| 5 | Paid Acquisition | Una campaña específica (Google Search, LinkedIn Ads, retargeting, paid social) | Una fuente controlada de demanda y aprendizaje sobre audiencia y mensaje. |
| 6 | CRM + Automation | HubSpot o Attio, pipeline, lead routing, follow-ups, enrichment, notificaciones | Que ninguna oportunidad se pierda por un olvido. |
| 7 | Tracking + Attribution | CRM, PostHog, ads, web, forms, UTMs, eventos de conversión | Saber qué campaña, página, mensaje y canal genera pipeline. |

*Brand* entra como **Positioning + Messaging**, no como «branding incluido»: si para vender hace
falta tocar identidad visual, diseño o dirección creativa, se hace, sin obligar a cada cliente a un
rebrand.

**Incluye (V1):** ICP y market targeting · offer, positioning y messaging · account research y
prioritization · outbound system · landing pages y conversion improvements · paid acquisition
experiment · CRM y automations · tracking y attribution · primeros experiments e iterations.

**Resultado tangible.** Al terminar no reciben una auditoría. Reciben: una lista activa de cuentas,
outbound funcionando, una web preparada para convertirlas, una campaña paga si corresponde, CRM
organizado, automatizaciones, tracking y un sistema de generación de pipeline operando.

**Equipo interno (oculto al cliente):** Market Research Specialist, ICP Analyst, Account
Researcher, Positioning Specialist, Copy Specialist, Web Specialist, Creative Specialist, Campaign
Analyst, Experiment Designer, Outcome Evaluator.

## Modelo operativo interno

Del export «27 Distribution». Cada trabajo termina con evidencia, no con «compiló»:

```
generation → deterministic verification → evidence → completion
durable context + ephemeral execution
```

| Línea | Pipeline |
|---|---|
| Lead generation | discover → enrich → dedupe → score → verify sample → deliver |
| Web | build → Playwright → screenshots desktop/mobile → errores de consola → layout checks → Lighthouse/performance → evidence |
| Contenido | generate → brand constraints → copy checks → dimension checks → visual comparison → export verification |

La biblia se enchufa en el paso de *copy checks* y en *decision*: `spread/tools/copy_audit.py`
corre sobre todo lo generado antes de entregarlo.
